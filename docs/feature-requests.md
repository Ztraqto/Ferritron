# Ferritron への機能の要望

2026-11-10、2.0.0（ブランチ `ferritron-2.0`、`c72816c`）を調べた上での要望です。問題点の記録
（[issues-2.0.0.md](issues-2.0.0.md)、[issues-2.0.0-part2.md](issues-2.0.0-part2.md)、[issues-2.0.0-part3.md](issues-2.0.0-part3.md)）から出てきたものと、
他のプラグイン フレームワークにあって Ferritron に見当たらないものを並べました。

- 「見当たらない」は、リポジトリ全体をキーワードで探して出てこなかった、という意味です。別の名前で既にあるかもしれません。
- 設計の原則（単純な核と、開いた拡張点）に合わせ、核に入れるものと拡張点として足すものを分けて書きました。
- 優先度は、**高** = 今ある機能が正しく動くために要る、**中** = 製品のプラグインを作るときに多くの人が要る、**低** = あると良い。

## 優先度が高いもの

### F1. ABI に `reset` を足す

- 今: `ferritron_plugin_api` に reset がない。`Process::reset` は `activate` の中でだけ呼ばれる。CLAP の `reset()` は空の関数、AU の `Reset` も届かない。
- 要望: `reset(instance)`（オーディオスレッド、`process` と同時には呼ばれない）を表の末尾に足す。`struct_size` で有無が分かるので、古いシムとも合う。
  中身は `plugin.reset()`、平滑化を目標へ飛ばす、スリープの状態と「押されているノート」を空にする。
- 使う場所: CLAP `reset`、AU `Reset`、VST3 の `setProcessing(false → true)`、バイパス解除（問題点 B2）。

### F2. 声の終了と打ち切り

- 今: シンセが「この声は鳴り終わった」とホストへ言う道がない。2.0 の `voice-info` と `poly = true` は、CLAP ではそれを前提にしている。
  `CLAP_EVENT_NOTE_CHOKE` も受けていない。`VoiceMods` はノートオフで声を忘れる（問題点 D4）。
- 要望:
  - `ctx.voice_ended(note_id, key, channel)`: 出力イベントとして積み、CLAP シムが `NOTE_END` にする。
  - `NoteKind::Choke`（または `ctx.midi()` の別の種類）: すぐ止める指示。
  - `VoiceMods::release(id)`（離した。変調は残す）と `VoiceMods::end(id)`（鳴り終わった。消す）。`feed_note` のノートオフは `release` にする。
  - 声の識別に `note_id` を使える `VoiceId`（同じキーの重なりを区別する）。

### F3. 区間ごとのトランスポート

- 今: ブロックを分割しても、`ctx.transport()` はホストのブロックの先頭の位置を返す（問題点 A3）。
- 要望: 区間ごとに `position_samples` と `position_beats` を進める。あわせて `ctx.block_offset()`（ホストのブロックの中でのこの区間の開始サンプル）を足す。
  ホストのブロックの長さ `ctx.host_frames()` もあると、ブロック単位の処理（FFT の枠など）を書きやすい。

### F4. 起床の条件

- 今: 起床は主入力、ノート、MIDI、パラメータの変更、`wake()` だけ（問題点 A2）。
- 要望: サイドチェーンの音でも起こす。加えて、プラグインが条件を足せる口:
  `fn wants_block(&self, hint: &WakeHint) -> bool`（再生が始まった、位置が飛んだ、など）。
  再生開始で音を出すもの（シーケンサ、メトロノーム）が `Tail::Infinite` にせずに済む。

### F5. 出力イベントを全形式で

- 今: `ctx.midi_out` と `ctx.set_param` の通知は VST3 と CLAP だけ。VST2・LV2・AU・AAX・スタンドアロン・プロセス隔離・WebAssembly では捨てる（問題点 B8）。
- 要望: LV2 は MIDI の出力ポート（Atom）、AU は `MIDIOutputCallback`、VST2 は `audioMasterProcessEvents`、隔離は共有メモリに出力の枠を足す。
  通せない形式は、ビルドのときに警告する（プロジェクト ファイルに `midi_output = true` を書かせ、対応しない形式を一覧にする）。

### F6. Windows の CI

- 今: ワークフローは `macos.yml` だけで、Windows でテストを回すジョブがない（問題点 E9）。「全例が VST3 `validator` に合格」は手で確かめた記録。
- 要望: Windows のジョブで `cargo test --workspace`、`cargo clippy`（今は `ferritron-dsp` のテストが deny の lint で止まる）、全例のバンドル、
  `ferritron-testhost`、VST3 `validator`、`clap-validator`、**pluginval**（リポジトリに一度も出てこない。多くの DAW の振る舞いをまねる検査で、
  スレッドの使い方や状態の往復を見る）。SDK は利用者が取るものなので、CI の秘密の保管場所かキャッシュから渡す形にする。
- あわせて `ferritron-bench-fx --compare` を回し、前の結果より遅くなったら失敗にする。

## 優先度が中のもの

### F7. 複数の出力バス

- 今: 出力は主バス 1 つ（VST3 の `getBusCount(kAudio, kOutput)` は常に 1）。入力は主バスとサイドチェーン。
- 要望: `[audio] outputs = [{ name = "Kick", channels = 2 }, ...]`。`ctx.io()` は主バスのまま、`ctx.output(i)` で他のバスを借りる。
  ホストがつないでいないバスは `None`。ドラムのシンセ、マルチバンドの帯域ごとの出力、モニター用の補助出力で要る。

### F8. パラメータのグループ

- 今: `[params.band] repeat = 24` で繰り返しは作れるが、ホストのパラメータ一覧では平らに並ぶ。VST3 の `IUnitInfo` はプログラムの一覧にだけ使っている。
- 要望: 繰り返しのグループと、`group = "Filter/Envelope"` のような指定を、VST3 のユニットと CLAP の `module` に出す。
  24 帯域 × 数項目のプラグインで、ホストのオートメーションの選択が使えるものになる。

### F9. 読み取り専用の出力パラメータ

- 今: メーターの値はストリームでエディタへ送れるが、ホストへは出せない。
- 要望: `[params] gr = { type = "float", ..., output = true }`。VST3 は `kIsReadOnly`、CLAP は `CLAP_PARAM_IS_READONLY`。
  オーディオスレッドから `ctx.set_output(&p, value)`。ホストのミキサーがゲインリダクションを表示できる（Cubase、Studio One）。

### F10. バイパスをプラグインが受け持つ

- 今: 組み込みのバイパスは、完全にバイパスしている間プラグインを呼ばない。ノートオフが届かず、残響が凍る（問題点 B2）。
- 要望: `[plugin] bypass = "builtin" | "process" | "custom"`。
  - `"process"`: クロスフェードは Ferritron がするが、バイパス中も `process` を呼び続ける（出力は捨てる）。状態が生きたままになる。
  - `"custom"`: `ctx.bypassed()` を渡すだけ。プラグインが自分で処理する（ドライ / ウェットの残響を残す、など）。

### F11. SysEx

- 今: `MidiData` は 3 バイト固定。SysEx はどの形式でも捨てる（AU の `sysex` は何もしない関数）。
- 要望: `ctx.sysex()`（そのブロックの SysEx のバイト列。シムのバッファを指すだけで写さない）と `ctx.sysex_out(&[u8])`。
  ハードウェアのエディタ / ライブラリアン、MTS（チューニング）で要る。

### F12. Linux

- 今: Linux にはエディタがない（README）。VST3 のメインスレッドのポーリングもない（問題点 B6）。
- 要望: VST3 は `IRunLoop` のタイマー、CLAP は `timer-support` と `posix-fd`、エディタは X11（Web は WebKitGTK、GPU は wgpu）。

### F13. 単発の裏方の仕事

- 今: `Worker` は一定間隔で呼ばれる常駐の仕事。「このファイルを読んで、終わったらオーディオスレッドへ渡す」には、自分でスレッドと `Swap` を組む。
- 要望: `instance.spawn(|| 重い仕事) -> Task<T>`。結果は `Swap` と同じ仕組みでオーディオスレッドが待たずに受け取る。
  古い値の解放もワーカー側でする（オーディオスレッドで `drop` しない）。サンプルの読み込み、インパルス応答の準備、表の作り直しで要る。
  スレッドは `Worker` と同じく最後のインスタンスで終わらせる（問題点 B3 と同じ扱い）。

### F14. DSP の部品

`ferritron-dsp` に見当たらなかったもの:

| 部品 | 用途 |
|---|---|
| サンプルレート変換（任意の比、窓つき sinc か多相） | サンプラー、ファイルの再生、スタンドアロンの入出力の合わせ |
| 畳み込み（分割 FFT、遅延なし / 低遅延） | リバーブ、キャビネット。CPU 版が見当たらない（GPU の例はある） |
| ADSR / 多段のエンベロープ、LFO | シンセ |
| 帯域制限つきのオシレータ（PolyBLEP、ウェーブテーブル） | シンセ |
| 声の割り当て（奪う順、同じキーの重なり、`NOTE_END` の発行） | シンセ。F2 と組にする |
| エンベロープ フォロワ（アタック / リリース、RMS、ピーク保持） | コンプレッサ、メーター |
| LUFS（BS.1770）とトゥルーピーク | マスタリング、メーター |
| STFT の枠（窓、重ね合わせ、ブロックの長さに依らない遅延） | スペクトル処理。区間の分割（A3）に左右されない形で |
| SIMD 版の `Oversampler` | 今はスカラー（問題点 P10） |

### F15. エディタ

- ファイルのドラッグ & ドロップ（外から中へ: サンプルやプリセット。中から外へ: MIDI やオーディオのクリップ）。リポジトリに出てこない。
- クリップボード（値の貼り付け、プリセットの写し）。
- エディタが使わないキーをホストへ返す（スペースで再生、など）。GPU エディタには `wants_key` があるが、Web エディタでの扱いが分からなかった。
- Web エディタの移動先の制限（問題点 D6）を既定にし、外へ出すリンクは `ferritron.open(url)` で既定のブラウザに渡す。
- 開発中だけ開発者ツールを開く指定（`FERRITRON_WEB_DEVTOOLS=1`）。
- リサイズの縦横比の固定（`[view] aspect = "16:9"`）。

### F16. プリセット

- 今: ファクトリプリセットはホストに見える。ユーザープリセットは Ferritron のフォルダの JSON で、ホストには見えない。
- 要望:
  - ユーザープリセットを CLAP のプリセット探索に出す（場所の種類 *file*）。VST3 は `.vstpreset` の書き出しと取り込み。
  - メタデータ（作者、分類、説明、お気に入り）。`[presets.<id>]` と JSON の両方に。
  - プリセットに `store`（パラメータ以外の状態）を含める指定。
  - `load_values` の値を、処理していないときにも読める / 保存できるようにする（問題点 A1 の直し）。
  - A / B の切り替えと、エディタの中のやり直し（Undo）の部品。値の束を持ち、`load_values` で入れ替えるだけのもの。

### F17. 計数とログ

- 今: 捨てた出力イベントの数（`OutQueue::dropped`）は数えているが、読む公開 API がない。シムが捨てたイベント、プールが足りずに
  フェードなしで切り替えたバイパス、`parallel_for` が直列に落ちた回数は、どこにも出ない。
- 要望: `instance.stats()`（原子的な計数の束）。`Harness` と `ferritron-testhost` で表示する。
- オーディオスレッドから書けるログ: `ctx.log(code, a, b)`（固定長の記録をロックなしのリングへ。別スレッドが文字にして出す）。
  今は `notify(code)` で代用できるが、値を添えられない。

### F18. スタンドアロン

- オーディオと MIDI のデバイス、サンプルレート、バッファ長を選ぶ画面と、その保存。
- ノート以外の MIDI を通す（問題点 D10）。
- テンポと再生 / 停止（`ctx.transport()` を埋める）。テンポ同期のプラグインを DAW なしで試せる。
- 2 チャンネルより多い入出力、サイドチェーンの入力。

### F19. 未定義動作の検査

- 今回の調査で、型では守られていない 1 スレッド専用の口がいくつか見つかった（`Seen`、ストリームの書き込み口、WebAssembly の `Store`、MCP のエンドポイント）。
- 要望: `ferritron-core` の単体テストを Miri で回す（`Seen` の `&mut` の重なりは Miri が見つける種類）。隔離と通知は ThreadSanitizer で回す。
  `state::deserialize` と `read_store` はファズにかける（ホストが渡すバイト列を読む唯一の入口）。
- `AllocGuard` と同じ考えで、オーディオスレッドでのロックの取得を数える検査（`LockGuard`）も足せる。

## 優先度が低いもの

- **F20. 64 ビット浮動小数点**: VST3 の `canProcessSampleSize` は 32 ビットだけ、CLAP の `data64` は見ない。計測用やマスタリング用のプラグインで求められる。
  `Process::process_f64` を任意で実装できる形にし、なければ今のまま 32 ビット。
- **F21. CLAP の拡張**: `param-indication`（ホストが割り当てた色やオートメーションの状態をつまみに出す）、`remote-controls`（ハードウェアのページ）、
  `note-name`（ドラムの名前）、`context-menu`（ホストのメニューをエディタから開く）、`state-context`（プリセットとして保存 / 複製として保存の区別。
  `InstanceId` を新しくするかどうかの判断に使える）。
- **F22. VST3 の拡張**: `IContextMenu`、`IParameterFunctionName`（「このパラメータがコンプレッサのスレッショルド」とホストへ伝える）、`IProgress`。
- **F23. アクセシビリティ**: GPU / FNG のエディタにスクリーンリーダー向けの木（Windows UIA、macOS NSAccessibility）を出す口。Web エディタは HTML の仕組みが使える。

## ホットリロード・GPU エディタ・GPU 処理・FNG からの要望（F26〜F45）

[issues-2.0.0-part3.md](issues-2.0.0-part3.md) を調べて出てきたものです。番号の後ろのかっこは、もとになった問題点です。

### ホットリロード

- **F26. すべての拡張を転送する（H1）**: 今のプロキシはレイテンシ・オフライン・エディタだけを返す。トランスポート、サイドチェーン、レイアウト、
  ホストとの連絡、トラック、メインスレッドの依頼、スリープ、エディタの大きさ、声の数、記述を、今のスロットへ転送する。
  あわせて「プロキシが返す拡張の一覧 = 核が返す拡張の一覧」を確かめるテストを置く（拡張を足したときに転送を忘れない）。
- **F38. 開いているエディタの差し替え**: 今は、開いているエディタは開いたときのコードのまま（閉じて開き直すと新しくなる）。
  リロードのときにビューを閉じて同じ親に開き直す。Web エディタは `ui/` のファイルを見張ってページを読み直すだけでも、UI の作業が速くなる。
- **F39. パラメータの一覧の変更（H4 の記録の 1 行）**: 今は記録に「プラグインを入れ直してください」と書くだけ。
  VST3 は `restartComponent(kParamTitlesChanged | kParamValuesChanged)`、CLAP は `rescan(CLAP_PARAM_RESCAN_ALL)` を送る。
- **F40. DSP の状態の引き継ぎ**: 今は新しいインスタンスを作り、状態（パラメータと `store`）を写す。ディレイや残響の中身は消える。
  `Process::hot_swap(&mut self, old: &dyn Any)` のような任意のフックで、型が変わっていないバッファを引き取れるようにする。
  既定は今のまま。
- **F41. 掃除と知らせ**: 起動時に、動いていないプロセスの一時ファイル（`<名前>-<pid>-<世代>`）を消す。リロードしたことをエディタへ
  `InstanceEvent` で知らせる（「リロードしました」の表示を作れる）。読み込みの失敗が続くときは間隔を空ける。

### GPU エディタ

- **F27. デバイスの喪失からの復帰（V1）**: 共有のデバイスを作り直せる形にする（`OnceLock` ではなく世代つき）。失われたら、
  エディタに `GpuEditor::device_lost` → `new` をやり直す。wgpu のエラーは受け口（`on_uncaptured_error`）で受け、記録して
  そのエディタを閉じる。ウィンドウプロシージャ全体を `catch_unwind` で包む。
- **F30. CPU 描画への切り替え**: GPU が使えないとき（仮想マシン、リモートデスクトップ、デバイスの喪失が続くとき）、FNG の `CpuRenderer` で
  描いてウィンドウへ転送する。FNG を使うエディタ（`FngAdapter`）はそのまま動く。wgpu を直接使うエディタには
  「GPU が使えません」の表示を出す。
- **F31. IME（V4）**: `Input::Composition { text, cursor }`（変換中）と `Input::Char`（確定）を出す。エディタは
  `ui.set_text_cursor(rect)` で候補ウィンドウの位置を伝える。Windows は `WM_IME_*` と `ImmSetCompositionWindow`、macOS は `NSTextInputClient`。
- **F32. 描画の間隔**: 入力による描き直しをペーサーに通す（V3）。表示の周期はウィンドウがいるモニターのものを使う。
  フレームを待つスレッドは、期限がないときは眠る（V6）。
- **F33. キャプチャとロックの後始末（V5）**: キャプチャを失ったら、押していたボタンの `Input::Release { cancelled: true }` を送り、
  ポインタのロックを外す。エディタの作者が個別に備えなくて済む。
- **F34. パラメータの変更を聞く口**: 今は GPU エディタが 16 ms ごと、Web エディタが 33 ms ごとに全パラメータを読む。
  インスタンスの `params_revision` と、変わったパラメータの一覧（ワーカーの `ChangedParams` と同じもの）をエディタへ渡す。

### GPU 処理

- **F28. 遅れからの復帰と状態（G1・G2）**: 遅れたら入力を捨てて今の位置から始め直す。`Convolver::status()`
  （正常 / 追いつき中 / GPU なし）を足し、変わったら `notify` でエディタへ知らせる。結果の受け渡しは待たない仕組みにする。
- **F35. 置き場所の固定（G4）**: `choose` の結果を状態に保存し、開き直したときは測らずにそれを使う。プロジェクト ファイルで
  `[gpu] placement = "measure" | "cpu" | "gpu"` を選べるようにする。書き出しと再生で同じ経路にする指定も要る。
- **F36. CPU 側の畳み込み（R1）**: 頭の部分を分割 FFT にする。同じ部品を `ferritron-dsp` に置けば、GPU のない環境での
  代わり（F14 の「畳み込み」）にもなる。
- **F37. 待ちの期限と作り直し（G3）**: GPU の結果を待つのに期限を付ける。超えたら GPU スレッドとデバイスを作り直す。
  `Convolver` の解放がメインスレッドを止めないようにする。

### FNG

- **F29. アトラス（N1・N2）**:
  - いっぱいになったら、長く使っていない棚から追い出す（`used` は既に記録している）。
  - マスクのキーから平行移動の整数部と描画先の大きさを外す。
  - 毎フレーム変わる図形のための指定: `scene.fill_path_dynamic(..)`（アトラスに残さない）。または、線や多角形を GPU で直接塗る道
    （波形やスペクトルのように頂点が多く毎回変わるもの向け）。
- **F42. 統計の重ね描き**: `PlanStats`（やり直しの回数、捨てた数、パスの数、アトラスの使用率）を、環境変数 1 つで画面の隅に出す。
  N1・N2 のような問題を、エディタの作者が自分で見つけられる。
- **F43. テクスチャの上限（N3）**: レイヤーやグループがデバイスの上限を超えるとき、分割するか縮小する。サーフェスも同じ上限で切る。

### 検査

- **F44. GPU の検査を CI で**: ソフトウェアの GPU（Windows の WARP、Linux の lavapipe）で、`ferritron-gpu` と FNG の GPU 側のテストを回す。
  今は GPU のあるマシンでしか確かめられない。FNG は CPU 版と GPU 版の絵を比べるテストを同じ仕組みで回せる。
- **F45. 検査用ホストの試験**: `ferritron-testhost` に、デバイスの喪失（デバイスを捨てる）、キャプチャの喪失、リサイズの連打、
  DLL のアンロードと読み直し（V2）を足す。どれも今回、読んで見つけただけで動かしていない。

### FNG の CPU レンダラ（F46〜F51）

[issues-2.0.0-part3.md](issues-2.0.0-part3.md) の「追記」（U1〜U10）から出たものです。今の CPU レンダラは基準の絵を作るためのもので、
倍率 2 の 1600 × 800 で 1 フレーム 23〜85 ms かかりました。F30（GPU が無いときのエディタ）に使うには、次のものが要ります。

- **F46. 実時間向けの描き方（U1）**: 変わった所だけ描き直す（前のフレームの命令列と比べる、またはエディタが変わった範囲を伝える）。
  画面を帯に分けて複数スレッドで描く。面を `[f32; 4]` から 8 ビットの乗算済み（または SIMD でまとめて扱える形）にして、メモリの読み書きを 1/4 にする。
  面と出力は使い回し、フレームごとに確保しない。
- **F47. 影（U3）**: 内側の一定の所と外側の何もない所を飛ばし、縁の帯だけ計算する。同じ影（大きさ・角・ぼかしが同じ）は 1 回描いて取っておく。
  実測で、画面に近い影 1 つが 1 フレームの時間を約 3.6 倍にしていた。
- **F48. 不透明度のグループ（U2）**: 中身の範囲（命令の外接矩形とクリップの重なり）だけの面を、使い回しの置き場から借りる。
  不透明度 1.0 のグループは面を作らずにそのまま描く。GPU 版にも同じ考えが使える。
- **F49. ミップマップ（U6）**: 画像を登録するときに縮小版を作り、縮めて描くときは近い段から取る。両方のバックエンドで同じ結果にする。
- **F50. 出力の口（U10）**: `render_into(&mut RgbaImage)` と、出力の形式（RGBA / BGRA、ストレート / 乗算済み）の指定。
  ウィンドウへの転送で、変換と確保を 1 回ずつ減らせる。
- **F51. 割り当て検査とグリフのキャッシュ（U1・U4・U5）**: `tests/alloc.rs` に CPU レンダラの「同じフレームは確保 0 回」を足す
  （今は GPU 側の準備だけ）。グリフのキャッシュはバイト数で上限を決め、長く使っていないものから捨てる（全部消すのをやめる）。
  回転した文字もキャッシュする。
